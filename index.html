QueryScope

Multi-Tenant Database Performance Monitor | .NET 10 & Angular 21
.NET 10 Angular 21 SQL Server Query Store Multi-Tenancy Clean Architecture

The Problem

Enterprise database clients require detailed monitoring of query bottlenecks, slow transactions, and deadlocks across multiple environments. However, doing so synchronously on a shared platform introduced high risk of cross-tenant data exposure and caused thread-pool starvation under high load.

Additionally, parsing execution plans and resolving XML deadlock graphs in real-time placed heavy strain on the primary API, leading to latency spikes for concurrent end-users.

Key Challenges
  • Risk of cross-tenant database metric leakage in a shared system.
  • Latency spikes during synchronous processing of heavy XML deadlock graphs.
  • Main API blocking during continuous query metric collection.

The Architecture

Engineered using Clean Architecture with .NET 10, strictly isolating the core domain logic from data access and frameworks. The system uses a multi-layered design separating Domain, Application, Infrastructure, Persistence, and Presentation boundaries.

To secure tenant data context, we configured Entity Framework Core global query filters tied to a dynamic tenant context provider to guarantee database-level multi-tenant isolation, automatically appending tenant parameters to every SQL statement.

To prevent performance bottlenecks on the primary web thread pool, query analysis and XML deadlock graph parsing were offloaded to a decoupled asynchronous background worker service (QueryScope.Worker). The frontend, built with Angular 21, implements a central HTTP interceptor that injects tenant context dynamically into headers to guarantee secure, automated multi-tenant API communication.

Key Integrations

  • EF Core Global Query Filters for tenant isolation.
  • Asynchronous Query Store metrics collector worker.
  • Angular 21 HTTP Interceptor for automated header injection.
  • Interactive deadlock graph visualization UI.

Solution Management System (BAUM Portal)

Enterprise Defect & ERP Sync System | KERN & SOHN GmbH (Germany)
.NET 8 Angular 16 Dapper ERP Integration Clean Architecture

The Problem

The legacy defect tracking system suffered from critical synchronization and query performance bottlenecks. Defect administration, repair procedures, and third-party repair tracking updates were heavily delayed.

Asynchronous operations regularly ran into lockouts due to high transaction loads under concurrent requests. The integration with the master ERP system created high data contention, leading to database deadlocks and slow API query speeds, directly degrading warehouse workflow productivity.

Key Challenges
  • Database deadlocks on high concurrency write cycles.
  • Highly delayed data synchronization with the legacy ERP.
  • Inefficient data layer handling that limited UI responsivity.

The Architecture

Refactored the application base into a Clean Architecture structure using .NET 8, decoupling core domain logic from infrastructure dependencies.

To resolve severe database contention, query reads were segregated from transactional writes by leveraging Dapper for optimized, low-latency database queries, while maintaining Entity Framework Core for complex transactional mutations. This CQRS-inspired decoupling eliminated database lockouts under peak load.

Integrated an asynchronous sync-agent communicating via message queues with the master SAP ERP system to prevent thread blocking during long-running integration tasks. The frontend utilizes Angular 16 dynamic rendering with DevExtreme load-on-scroll grids to render tens of thousands of repair records efficiently.

Key Integrations

  • CQRS pattern segregation for data layers.
  • Dapper micro-ORM for high-throughput reads.
  • Async SAP ERP sync service via message queueing.
  • Angular 16 dynamic list grids.

Academy Locksmith’s Skynet

High-Scale Dispatch SaaS & Payments Platform | U.S. Dispatch
.NET MVC SQL Server Azure Services REST APIs Geocoding Map APIs

The Problem

Skynet serves as a high-scale nationwide U.S. dispatch service managing locksmith operations in real-time. High load during peak emergency dispatch slots caused transactional delays, payment gateway timeouts, and delayed technician routing notifications.

The on-site technicians suffered from dropped connections, which led to synchronization delays between mobile status updates and the centralized dispatcher web views. Payment processing delays also prevented prompt job confirmations.

Key Challenges
  • Payment failures due to synchronous timeout exceptions.
  • High mapping and routing overhead calculations.
  • Mobile API response latency under poor coverage.

The Architecture

Designed a scalable distributed service architecture built on ASP.NET MVC and Azure. Outbound payment gateway integrations (Stripe) and background notification dispatches were decoupled using Azure Service Bus queues, ensuring transactional safety and preventing request timeouts under peak scheduling hours.

Implemented Redis caching layers to store routing matrix calculations and optimized SQL Server clustered database indexes for geographic lookups. Built compressed REST Web API payloads utilizing GZIP compression to minimize overhead for field operations, ensuring technicians could sync location updates under low network coverage.

Key Integrations

  • Azure Service Bus message queues for payment safety.
  • Redis caching for heavy routing matrix queries.
  • Clustered database indexes for fast geographic query dispatches.
  • Compressed REST APIs for mobile field operations.

Softfolio Sage

Mobile ERP Client & Sage100 Synchronization Engine | Mobile ERP App
Xamarin SOAP API Sage100 ERP SQLite Offline Cache Async Sync Queue

The Problem

Warehouse operations require real-time updates for barcodes, inventory, and stock counts. However, warehouse corridors are frequently "dead zones" for Wi-Fi and mobile connectivity.

Workers experienced constant application crashes, record duplication, and severe lag when the mobile device tried to communicate directly with Sage100's legacy, high-overhead SOAP API during scanning tasks.

Key Challenges
  • Lost data when barcode scanners lost network connection.
  • Extremely slow execution times for complex SOAP API requests.
  • High device battery drain due to repeated connection attempts.

The Architecture

Built an offline-first mobile synchronization client using Xamarin.Forms and SQLite. Leveraged SQLite on the mobile scanner device to persist scan transactions immediately, securing records before network validation.

Engineered a background sync coordinator that checks connection state, throttles SOAP XML payloads (stripping redundant schemas and achieving a 60% reduction in size), and executes safe batch updates to the Sage100 ERP database on reconnect. Built thread-safe write locks using SemaphoreSlim to avoid lock collisions during synchronization.

Key Integrations

  • Offline-first SQLite local caching architecture.
  • Background scan synchronization manager.
  • SOAP XML payload compression.
  • Thread-safe async write locks on database layers.
