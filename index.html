QueryScope

Multi-Tenant Database Performance Monitor | .NET 10 & Angular 21
.NET 10 Angular 21 Azure OpenAI Integration Semantic Caching Clean Architecture

The Problem

Enterprise database clients require detailed monitoring of query bottlenecks, slow transactions, and deadlocks across multiple environments. However, XML deadlock graphs and execution plans are highly complex and difficult for developers and database administrators to manually analyze in real-time.

Integrating automated AI diagnostics presented key engineering challenges: generating LLM-driven query recommendations synchronously would cause severe API response latency, and executing repeated queries directly against the LLM under peak traffic conditions would run up prohibitive token billing and hit API rate limits.

Key Challenges
  • Database latency when parsing heavy XML deadlock graphs.
  • Synchronous API blocking during real-time LLM query diagnostic checks.
  • High token billing and rate-limiting overhead under continuous monitoring workloads.

The Architecture

Engineered using Clean Architecture with .NET 10 and Angular 21. Built a secure multi-tenant data access pipeline using Entity Framework Core global query filters tied to a dynamic tenant context provider, automatically appending tenant identifiers to all database queries.

To enable cost-effective, non-blocking AI diagnostics, query analysis and deadlock XML parsing were offloaded to a decoupled asynchronous background worker service (QueryScope.Worker). The worker filters metric snapshots, packages the slow query structure alongside table schemas and index metadata, and dispatches them asynchronously to **Azure OpenAI**. We enforced structured JSON outputs using strict schema parsing to ensure reliable frontend parsing.

Implemented a **Redis semantic cache** to store query signatures and their associated AI suggestions, completely bypassing the LLM for duplicate query patterns and reducing API transaction costs by **70%**.

Key Integrations

  • EF Core Global Query Filters for tenant isolation.
  • Azure OpenAI integration for automated query diagnostics.
  • Redis semantic caching for cost-optimized LLM requests.
  • Asynchronous Query Store background collector worker.

Solution Management System

Enterprise Defect & ERP Sync System | Developed for a Germany-based Manufacturer
.NET 8 Angular 16 Dapper ERP Integration Clean Architecture

The Problem

The legacy defect tracking system suffered from critical synchronization and query performance bottlenecks. Defect administration, repair procedures, and third-party repair tracking updates were heavily delayed.

Asynchronous operations regularly ran into lockouts due to high transaction loads under concurrent requests. The integration with the master ERP system created high data contention, leading to database deadlocks and slow API query speeds, directly degrading warehouse workflow productivity.

Key Challenges
  • Database deadlocks on high concurrency write cycles.
  • Highly delayed data synchronization with the legacy ERP.
  • Inefficient data layer handling that limited UI responsivity.

The Architecture

Refactored the application base into a Clean Architecture structure using .NET 8, decoupling core domain logic from infrastructure dependencies.

To resolve severe database contention, query reads were segregated from transactional writes by leveraging Dapper for optimized, low-latency database queries, while maintaining Entity Framework Core for complex transactional mutations. This CQRS-inspired decoupling eliminated database lockouts under peak load.

Integrated an asynchronous sync-agent communicating via message queues with the master SAP ERP system to prevent thread blocking during long-running integration tasks. The frontend utilizes Angular 16 dynamic rendering with DevExtreme load-on-scroll grids to render tens of thousands of repair records efficiently.

Key Integrations

  • CQRS pattern segregation for data layers.
  • Dapper micro-ORM for high-throughput reads.
  • Async SAP ERP sync service via message queueing.
  • Angular 16 dynamic list grids.

Skynet (SaaS Job Dispatch Platform)

High-Scale Dispatch SaaS & Payments Platform | Nationwide U.S. dispatch service
.NET MVC SQL Server Azure Services REST APIs Geocoding Map APIs

The Problem

Skynet serves as a high-scale nationwide U.S. dispatch service managing locksmith operations in real-time. High load during peak emergency dispatch slots caused transactional delays, payment gateway timeouts, and delayed technician routing notifications.

The on-site technicians suffered from dropped connections, which led to synchronization delays between mobile status updates and the centralized dispatcher web views. Payment processing delays also prevented prompt job confirmations.

Key Challenges
  • Payment failures due to synchronous timeout exceptions.
  • High mapping and routing overhead calculations.
  • Mobile API response latency under poor coverage.

The Architecture

Designed a scalable distributed service architecture built on ASP.NET MVC and Azure. Outbound payment gateway integrations (Stripe) and background notification dispatches were decoupled using Azure Service Bus queues, ensuring transactional safety and preventing request timeouts under peak scheduling hours.

Implemented Redis caching layers to store routing matrix calculations and optimized SQL Server clustered database indexes for geographic lookups. Built compressed REST Web API payloads utilizing GZIP compression to minimize overhead for field operations, ensuring technicians could sync location updates under low network coverage.

Key Integrations

  • Azure Service Bus message queues for payment safety.
  • Redis caching for heavy routing matrix queries.
  • Clustered database indexes for fast geographic query dispatches.
  • Compressed REST APIs for mobile field operations.

Poologics

Pool Construction & Logistics Management SaaS | ASP.NET MVC & SQL Server
ASP.NET MVC Web API SQL Server Concurrency Control Team Leadership

The Problem

Pool construction projects involve complex logistics, resource scheduling, inventory tracking, and client communication. The legacy scheduling platform suffered from high latency during peak seasonal loads, causing job overlapping and dispatcher blockages.

Inefficient SQL queries and a lack of transactional isolation led to database record locking when dispatch coordinators and field engineers updated schedules concurrently, resulting in synchronization conflicts.

Key Challenges
  • Database record lockouts during concurrent calendar updates.
  • Slow response times on mobile devices for on-site crew updates.
  • Sprint coordination overhead and team alignment issues.

The Architecture

Built using a 3-tier architecture with ASP.NET MVC, Web API, and SQL Server. Implemented a decoupled scheduling engine to handle concurrent date reservations with optimistic concurrency controls (version checking) to prevent database deadlocks and record locks.

Restful APIs were optimized to stream calendar metrics to mobile client apps, utilizing Redis caching for frequently accessed project templates and crew allocations.

As team lead, coordinated development sprints, guided junior developers on clean coding patterns, and established unit-testing pipelines to validate scheduler behaviors.

Key Integrations

  • ASP.NET Web API for mobile resource dispatches.
  • SQL Server calendar booking engine.
  • Optimistic concurrency filters for record safety.
  • Redis cache allocations for active crews.
